Documentation technique — importInrap

Plugin CollectiveAccess Providence — INRAP

Vue d’ensemble

Le plugin importInrap permet d’importer des données depuis des fichiers Excel (XLS/XLSX) dans la base CollectiveAccess, avec un processus en 5 étapes guidées : upload du fichier, sélection de la feuille, mapping des colonnes, sélection des lignes, puis import paginé.

Le plugin gère 8 types d’import : mobilier archéologique, objets musée, opérations, documentation numérique, documentation écrite, contenants mobilier, contenants documentation et contenants numériques.

Rôle du plugin

  • Importer des objets, collections et documents depuis des fichiers Excel
  • Mapper interactivement les colonnes Excel vers les champs CollectiveAccess
  • Créer ou mettre à jour les enregistrements existants (détection par idno)
  • Gérer les relations : collections, entités, lieux, emplacements, mouvements, contenants
  • Traiter les attributs complexes : containers (dimensions, notes), valeurs multiples
  • Import paginé (1 ligne par requête HTTP) avec barre de progression
  • Déclencher les hooks hookSaveItem après chaque import

Hooks utilisés

  • hookRenderMenuBar — Ajoute un menu « Import Inrap » dans la barre de navigation
Aucune restriction de rôle — getRoleActionList retourne un tableau vide.

Processus d’import (5 étapes)

Étape 1 — Upload du fichier et sélection du type (Index)

L’utilisateur sélectionne le type d’import et uploade un fichier Excel :

  • Mobilier archéologique / Objets musée / Opérations
  • Documentation numérique / écrite
  • Contenant mobilier / documentation / numérique

Étape 2 — Sélection de la feuille (SelectSheet)

PhpSpreadsheet charge le classeur et affiche la liste des feuilles. L’utilisateur choisit celle à importer.

Étape 3 — Mapping des colonnes (SelectBeforeImport)

Le système lit les en-têtes et affiche un formulaire de mapping (en-têtes Excel ↔ champs CA). Un script jQuery tente un auto-matching par similarité de nom.

Étape 4 — Sélection des lignes (SelectLineBeforeImport)

Les données sont mappées et sauvegardées en JSON. L’utilisateur coche les lignes à importer.

Étape 5 — Import paginé (Import)

Import ligne par ligne avec barre de progression. Pour chaque ligne :

  • Appelle _importObject() ou _importCollection() selon le type
  • Auto-submit après 500ms pour la ligne suivante
  • Page de succès avec liens vers les fiches créées en fin d’import
Mémoire et temps : l’action Import() définit memory_limit = -1 et max_execution_time = 0.

Fonctions d’import (lib/)

_importObject() — Import d’objets

Fichier : lib/_importObject.php

Fonction principale pour tous les types d’objets. Processus :

  1. Chargement ou création par idno
  2. Champs spéciaux : poids (unité), dimensions (cm), titre, titre document, containers
  3. Relations : ca_collections, ca_entities, ca_places, ca_objects (contenants), ca_storage_locations, ca_movements
  4. Attributs standards : suppression puis ajout. Valeurs multiples (séparateur « ; ») si canBeMultiple = 1
  5. Containers : suppression des existants, insertion des nouveaux
  6. Hooks : appel de hookSaveItem()
Création automatique de contenants : si le contenant référencé n’existe pas dans l’opération, la fonction le crée automatiquement (type 28) et le rattache à la collection.

_importCollection() — Import d’opérations

Fichier : lib/_importCollection.php

Même structure que _importObject() pour les collections (ca_collections, type 125). Relations : ca_places, ca_entities, ca_storage_locations, ca_movements. Appelle hookEditItem() en fin de traitement.

PhpSpreadsheet requis : la bibliothèque PhpOffice/PhpSpreadsheet doit être installée via Composer.

Activation

Le plugin est activé par défaut (enabled = 1).

Prérequis

  • PhpSpreadsheet installé via Composer
  • Répertoire temp/ accessible en écriture
  • Mapping configuré dans conf/importInrap.conf
  • Types d’objets et relations référencés existants dans la base
